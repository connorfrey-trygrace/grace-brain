# Subscriptions

**What this is for.** Recurring paid tools charged to Connor's card or Grace's, with the renewal date, the expense code, and who pays. **Read it before buying a tool and once a month when the coding sheet comes around** — not on every refresh run.

**Why it exists (2026-08-18).** The vault had no home for a recurring charge. Zoom went in as an action note in July, that note was archived when the *signup* completed, and **its renewal went with it** — the charge recurs but nothing in the vault knows when. AhaSlides was about to repeat the pattern the same way: bought 2026-08-18 on a 12-month term, tracked only inside an action note about building a question rank. An action note closes when the action is done; a subscription doesn't stop costing money when you finish setting it up. Those are different lifecycles and they need different files.

**Rules**

- A row goes in here **the day something is purchased**, not at renewal time.
- `Auto-renew` is the field that actually matters. Both entries below auto-renew by default; that is how these plans are sold.
- **Never invent a renewal date.** It comes from the receipt or the vendor's term, and both are external. If a receipt doesn't state one, write `unknown` and say so.
- Expense codes come from Derek Adye's 2026-08-04 ruling; software and meeting tools are **9003**. Confirm the card before coding — a personal card means a reimbursement, not a code.
- When a subscription is cancelled, keep the row and mark it `cancelled` with the date. The point of the file is remembering that money used to leave, and when it stopped.
