# Room reservation is the Rock "Event Request" form — and the Outlook auditorium calendar can't be trusted to check availability

Connor asked how a room gets reserved ("I think it is the rock form") and to look at the auditorium's Outlook calendar. Both were checked live.

## The path

Rock homepage → Quick Links → **"Event Request"** → `https://trygrace.rockcloud.com/eventregistrationrequest`. Same URL this workflow already documented as "Form 2 — Event Registration Request," so Connor's instinct was right — but the file described a registration form, not a facility request, and the form itself has changed.

It now does both jobs. Its own intro: *"This will help us determine if we have the staffing and resources necessary to hold your event on the date/time you have requested… more information regarding use of our facilities."* The facility side routes to **Callie Taylor, Events Coordinator**, who replies on a thread titled *"Following up on MM/DD/YYYY Event Request."* Registration still routes to Kay Carter-Corker.

**There is no room picker.** The only location field is *Where is your event taking place? → Grace / Not at Grace*. The room has to be named in the description or Special Instructions. New since this file was written: a resources checklist (Tables, Chairs, Tablecloths, Audio Board, ProPresenter/Lights, Custodian, Special cleaning, Police/security, Coffee bar, Facilities support). Gone: *"Will the link be posted on the Grace website?"*

## The Outlook auditorium calendar — measured, not assumed

`Auditorium@trygrace.org` is a real resource mailbox in the org directory. It is not on Connor's calendar list; free/busy reads fine without adding it.

| probe | result |
|---|---|
| Sun 9/6, 8:00 AM–1:00 PM ET | **busy** — morning services + run-through |
| Sun 9/20, 5:00–8:00 PM ET | **busy** — Sunday Night |
| Sun 9/27, 5:00–8:00 PM ET | **busy** — so the SNL block is a standing recurrence, not a one-off |
| Thu 9/3, all day | free |
| Wed 9/9 & Thu 9/10, all day | free |
| **Mon 8/10, all day** | **free — and Heather Noble's Raise Media auditorium shoot ran that day**, filed through the Event Request form and handled by Callie |

**Conclusion: a busy block is trustworthy; a free block is not.** Recurring services are on the mailbox. One-off events approved through the Event Request form are not — nothing writes back to it.

## The question that is still open

Heather Noble asked Callie Taylor directly on 2026-08-06: *"Please let me know if there is a better way to check on room availability before filling out the request form."* **Callie did not answer it in that thread**, and three weeks later the answer is still "there isn't one you can rely on." Recorded, not chased — this is Callie's system to describe, and per [[church-not-a-corporation]] it is a question to ask once in conversation, not a ticket to escalate.

## Resolved same day — the practical answer

Connor, 2026-08-28: **"I walk in after the run through."**

So the Event Request form is for *events* — a booked, staffed, resourced occasion. A staff member using the auditorium for an hour on a weekday after the run-through is not one, and does not get filed. That is why the mailbox looks empty on weekdays and why the 9/3 screen test needs nothing beyond showing up.

It also narrows what the availability gap actually costs. The mailbox misses one-off *approved events* (Heather's 8/10 shoot), and it also never sees informal staff use — which is most weekday use of the room. Neither is a defect to fix; it is what the system is.
