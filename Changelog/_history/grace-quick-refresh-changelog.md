## Changelog
- 2026-08-11: Added **§ Timing** — `date '+%s'` at each phase boundary, one line per refresh appended to the new [[Logs/refresh-run-log]], plus an `elapsed Xm` field on both syncs' own Run Log lines. Tier 2 (new observability step). Trigger: Connor asked why the 2026-08-11 quick refresh took ~30 minutes; the vault held no timing data at all, so the answer came from file mtimes — which showed a **48-minute window with zero writes** and could say nothing about what happened inside it.
- 2026-08-10 (3): **Added Phase 0 — process new transcripts** to both this routine and `grace-weekly-refresh`. Nothing in the system promoted `unprocessed` → `processed` automatically; speaker-ID + synthesis were on-demand-only, so three transcripts (7/22–7/30) sat unprocessed for two weeks while the weekly synthesis could only flag them. Phase 0 scans `/Transcripts/` for the `unprocessed` tag and runs speaker-ID + synthesis, gated on speaker confidence: unambiguous transcripts process automatically; ambiguous ones get an inline confirmation in this on-demand routine, or are deferred + flagged in the unattended weekly run (never guess a speaker unattended). Runs first so synthesis-minted action items are in place before the Phase 3 sweep. Also updated both scheduled-task prompts and [[Trackers/Automation]]. Tier 3 (new phase across two workflows + both task prompts). Trigger: Connor — after processing the backlog, "adding transcription processing into the quick refresh and weekly refresh workflows is good. Do that too."
- 2026-08-10 (2): **Report restructured to lead with a work queue.** Connor: "whenever I invoke it, I am usually sitting down to get work done, so having immediate priorities and actions surfaced would be helpful." Part 1 is now **Start here** — `actions-index.py --brief`, which returns only overdue/due-today, this-week, decisions awaiting Connor, unparked items, and flagged/stalled, grouped and capped — with a standing instruction to name the *next physical action* rather than the item title, and an explicit rule not to pad the list when it's short. Part 2 (what the sync actually changed) drops below it; run counts and health chatter move to `/Logs` entirely. Tier 2 (report format). Trigger: Connor.
- 2026-08-10: **Restructured into three phases so the two source pulls run concurrently.** The text scan and email sync have no data dependency on each other — only the sweep depends on both — but they had been running strictly in sequence. Analysis is now parallel; **writes were deliberately kept sequential** (email first, then text) because both jobs edit the same notes in `/Trackers/Actions/` and a concurrent-write collision would silently drop one edit with no error anywhere. Landed alongside the log split (procedure text 142 KB → 58 KB) and [[Workflows/actions-index.py]] (Step 0 of the sweep; ~430 KB of note bodies → ~8 KB index). Tier 2 (execution-model change). Trigger: Connor asked why the quick refresh takes so long; measurement showed ~570 KB / ~145k tokens read per run before any decision was made.
- 2026-07-21: Created alongside `grace-weekly-refresh`, replacing the fixed 8am/12pm/4pm email-sync cadence and daily 8am text-scan cadence. Tier 3 (new on-demand workflow + scheduling model change). Trigger: Connor's request — both goals were true (the fixed cadence was noise *and* insufficient), so he wanted an on-demand pull for actual work sessions plus a weekly floor underneath it.
