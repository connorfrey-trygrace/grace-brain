- 2026-08-04: **Two mechanics notes from this run, both worth a decision from Connor.** (1) The **mount tail is not stable** — Source & access says `mnt/Library--Messages/`, corrected 2026-07-24; this session exposed it as **`mnt/connorfrey--Library--Messages/`**. The tail is derived from the device path, so it varies. Recommend the workflow stop naming a literal tail and instead say: *list `/sessions/*/mnt/` and pick the entry ending in `Library--Messages` (the one containing `chat.db`), not the `System--Library--Messages` one.* (2) **`pip install pytypedstream` — promoted in the 2026-08-03 changelog — is not always possible.** The device shell has no network access, so on this run the library could not be installed, and `chat.db` (348 MB) failed to upload to the cloud container where pip does work. Fallback used, and it should be written into Step 2 as the documented Plan B: a targeted typedstream parser (find `NSString`, then the next `+` type marker, then the variable-length int — `<0x80` literal, `0x81`→ 2-byte LE, `0x82`→ 3, `0x83`→ 4 — then that many UTF-8 bytes), **and — this is the part that matters — self-validate it before trusting it** by running it against every message in the window that has a non-empty `text` column and requiring 100% exact agreement. This run got 67/67, then decoded 84/84 in-scope messages with 0 garbled. That validation step is the direct answer to the 7/28 lesson ("the check for whether a fix works has to be a measurement, not a re-reading") — a decoder that silently degrades cannot hide behind a clean-looking report if it must first reproduce known-good text. Tier 1 (log entry + two standing recommendations; no procedure change made unilaterally).
